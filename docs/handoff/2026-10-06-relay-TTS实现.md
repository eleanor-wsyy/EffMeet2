# LiveKit relay 与真实 TTS 实现交接

本轮工作目录为 `F:\素材1\eff2\EffMeet2-main`，仅处理远程音轨转发和 TTS 两项。

## 实现

- LiveKit token 端点保留原路径，签发前连接本会议 relay；远程身份从请求认证确定，只允许 remote_1/remote_2。房间绑定 meeting_id，发布限定 microphone，禁止视频和数据发布。订阅音轨保留以支持互听，不能冒用其他人的身份发布。
- relay 只接远程麦克风音轨，SDK 转为 16 kHz 单声道 PCM；静音 0.8 秒或最长约 5 秒切段，队列上限 4 段，串行调用 FunASR，channel=remote、source=livekit_remote_asr 入账。当前阈值切段不是完善的 VAD/AEC。
- 每会议一个订阅连接；重复订阅取消旧消费任务；段 ID 生成确定性 utterance_id。队列过载或 ASR 错误可丢失该段并记录错误，不宣称无损重连。
- 状态查询：GET `/api/v1/meetings/{meeting_id}/livekit-status`，需本人认证，返回连接、消费任务数及最近错误。
- 保留团队 TTS 语速 -1，并增加参数范围检查。真实播放测试支持 `scripts/smoke_bench.py --real-tts`；仅 TTS 和电脑音频输出为真实，ASR/模型和确认场景为测试夹具。

## LiveKit 配置及 D 对接

服务不自动加载 .env。在启动服务的终端设置 LIVEKIT_URL、LIVEKIT_API_KEY、LIVEKIT_API_SECRET，以及 FUNASR_WS_URL。密钥不进前端、文档或 Git。

先启动本地 ASR，再设置 EFFMEET_TTS=windows 并运行 scripts/run_bench.py。POST `/api/v1/meetings/{meeting_id}/livekit-token` 使用本人 Bearer token，JSON 为 `{}`；返回 token/url/room，D 用 JS SDK connect、开启麦克风、静音和 disconnect。房间由首个加入连接创建。缺配置返回 503，连接失败返回 502，不静默替换为模拟。

任务单“token 接口不出现在前端”应理解为签名密钥与签发实现不进前端；前端调用端点地址是必要的。

## 验收边界

本轮在当前目录执行的测试：65 项单元测试；真实 TTS 冒烟返回 PASS，使用 Windows TTS + host audio，经过真实 HTTP/WebSocket、音频帧 ACK、播放器排空回执、重复决定去重和事件恢复。人工听声确认尚未取得，不能据此宣称扬声器声学效果已验证。

尚未配置真实 LiveKit 服务，因此双浏览器互听、静音、真人远程转写和断网重连未实测。SDK 支持短时重连，彻底断开后需重新调用 token 端点；不能据此标记断网验收通过。当前认证为本机测试角色，生产成员认证未实现。D 的前端与手机访问部署不在本轮两项范围，控制器仍仅允许本机访问。
