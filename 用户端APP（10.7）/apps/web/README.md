# EffMeet2 · Figma 手机用户端接入说明

日期：2026-10-07。基于仓库快照 aa7cdab 和 Figma 文件 BKYW6vJEcICpnBrzvM3CXa。

## 本轮范围

实现的是 Figma 的参与者手机界面：入会页、会中页、观点地图页。不是主持人/调试工作台。
- /app/：新增/重构的手机用户端。
- /：保留原有主持人/调试入口。
- demo.html、bench.html、camera.js、audio.js 与原始仓库逐字节一致。
- 没有改动 Figma 云端文件。本次作为 `用户端APP（10.7）` 独立目录提交至 GitHub；没有公网部署。

## 本次追加：视觉精修与多候选演示

- 视觉改动仅发生在 styles.css：保留白色 → #FFEFBA 底图渐变，收敛大面积珊瑚橙，统一标题层级、留白、细边框、轻阴影及底部弹层。
- index.html、app.js、state.js 与本次修改前内容完全一致；没有更改现有 UI 文案、按钮事件、三屏导航或候选处理流程。
- 演示脚本默认生成 4 条独立候选，新增内容仅为人工合成的会议证据，不是改写 UI 文案或真实会议记录。保留原有第一条演示内容。
- 所有演示原话先写入，再分别创建候选，让候选共享同一证据上下文；不会因为逐条造数据而让前一条立即失效。
- 每条候选使用独立 ID、证据和决定状态。确认一条不代替其余条目作决定；后端鉴权、120 秒时限、上下文检查及幂等保护保持原样。

## 直接运行

在 `用户端APP（10.7）` 目录打开终端（不是外层仓库根目录），使用隔离 Python 环境：

~~~powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-media.txt
./.venv/Scripts/python.exe scripts/run_participant.py
~~~

访问 http://127.0.0.1:8765/app/ 。前端无需 npm 安装或打包；静态资源与后端同源服务。
若需要自选端口/隔离数据：

~~~powershell
./.venv/Scripts/python.exe scripts/run_participant.py --port 8876 --db .local/participant.sqlite3
~~~

数据库会存储会议证据；不要提交 .local/ 或其他测试数据库。服务只监听本机，不修改安全保护。

另开一个终端，创建明确标记为合成数据的模拟会议：

~~~powershell
./.venv/Scripts/python.exe scripts/seed_participant_demo.py
~~~

若服务在 8876，给 seed 脚本同样传入 --port 8876。默认生成 4 条独立的待确认；可传 --candidates 1、2、3 或 4。它会输出用户端邀请链接和会议 ID。

~~~powershell
./.venv/Scripts/python.exe scripts/seed_participant_demo.py --port 8876 --candidates 4
~~~

演示时可逐条打开「查看状态」并点击「请机器人提醒」。需要重新演示一整组未处理候选时，再运行一次脚本创建新会议，不重置已处理记录。
在入会页输入链接/ID、任意联调昵称，默认联调身份为线上成员 1（remote_1），然后进入会议。
候选自创建起 120 秒过期。不能通过收起/重开或轮询延长有效期；在「查看状态」中主动点击「请机器人提醒」时，过期候选会请求后端重新校验，只有原证据上下文未变化、仍满足提醒条件且未作出决定时才续签候选版本并提交确认。现场已回应、有新发言或已处理时会阻止提醒。
seed 仅支持 mock 模式，不调用真实模型或机器人。

## 相对于 Figma 的交互修正

1. 保持 3 屏结构、珊瑚橙按钮及白色圆角卡片；页面底图按用户要求改为从左到右的 #FFFFFF → #FFEFBA 渐变（含 #FFEFBA 纯色回退），控件内部原有暖灰底色保留，使用 Figma 原图标资源；长内容在手机容器内部滚动，不按画布上重叠的绝对位置堆放。
2. 会议链接和昵称是实际输入框；无效输入时禁止入会，合法填写后启用。
3. 地图入口在会中页顶部直接可见；左滑进入地图、右滑返回会中，也可使用按钮。浏览地图不代表会议结束。
4. 候选从手机底部向上滑入，遮罩淡入，不从上方掉落。点击遮罩/收起只关闭界面，不等于选择不必提醒。
5. 只自动展示属于本人且仍有效的新候选。同一候选不反复弹出；地图或后台期间到达的候选留在待确认列表，返回后不突然打断。
6. 提醒状态由服务器回执驱动，不通过假延时伪造排队/播报。模拟后端可能直接返回完成，此时不会假装播报几秒。
7. 已提醒不等于已回应；观点地图仍按真实分析/核对证据展示可能未回应或已回应。
8. 「查看状态」弹层保留「请机器人提醒」操作：有效候选直接确认；过期候选先校验再确认。完成、拒绝或已回应后禁用，不重复播报；请求期间禁止连点。
9. 有焦点约束、Escape 收起、减少动画偏好及禁用状态保护；轮询未改变内容时不重建证据卡，避免查看原话被打断。

## 实际接口

- GET /api/demo/session：原有本机联调身份令牌（不是正式登录）。
- GET /api/demo/meetings/{id}/state：实时会议、发言、候选及回执。
- POST /api/v1/meetings/{id}/interventions/{id}/recheck：仅本人主动点击时重新校验过期候选；检查版本、原话上下文、回应情况及未决定状态，不直接发送机器人命令。
- POST /api/v1/meetings/{id}/interventions/{id}/decision：本人确认/拒绝，带 expected_revision；保留后端的身份、TTL、上下文检查及幂等保护。
- GET /api/v1/meetings/{id}/viewpoint-map：真实观点与证据。
- GET /api/v1/meetings/{id}/captures：现场原图列表；读取原图时携带原有认证。
- 导出：JSON 证据包，含观点地图、原话、候选和回执，不是伪造会后总结。

后端增加同源 /app 挂载、server_time/expires_at、观点源数据 revision，以及本人主动重新校验候选接口。原 decision 的身份、TTL、上下文及幂等检查保留；不改工作台。

## 已验证

- Python unittest：88 项通过（含原用户端集成、多候选演示及 HTTPS 网关测试）。
- Node：32 项通过；app.js/state.js 语法通过。
- 浏览器实测：输入启用入会、真实入会、底部候选、遮罩收起、重开不重置倒计时、确认回执、不必提醒关闭、左右横滑、地图期间候选不打断、原话展开、JSON 文件落盘。
- 本轮浏览器实测：过期候选「查看状态」→「请机器人提醒」可点击→后端重新校验并确认→收到本机模拟完成回执→按钮禁用、禁止重复提醒；浏览器错误日志为空。
- 多候选浏览器实测：4 条候选同时出现；分别确认 2 条，待决定数量从 4 → 3 → 2；另外 2 条仍保留自己的状态。完成回执禁止重复提醒。
- DOM 尺寸实测：390×844 手机容器，无页面横向溢出；地图入口处于首屏，弹层下沿贴齐手机下沿。320×720 小屏弹层也无横向溢出，两按钮高度约 50px。
- 保存了浏览器截图供人工审阅。当前环境不支持读取截图像素，未声称完成逐像素视觉比对。

## 明确尚未完成的能力

- 正式账号、身份绑定和公网手机访问：现有控制器为 local-only；昵称仅用于本地显示，本机 remote_1/remote_2 不是生产账号。
- 麦克风按钮目前做真实权限检查后停止收音。前端还没有接通 LiveKit 音频发送，不能称为已录音/已上传，也不显示假的常亮录音红点。
- 现场 AI 描述接口尚不可用；不把文件名或假文案当描述。
- 真实机器人、现场安全停顿、模型与音频链路仍需按硬件台架配置联调。本地预览用模拟机器人回执。
- 后端没有会议结束事件/接口，尚不能按结束事件自动跳地图。地图浏览和证据导出可用。
- 已提供 manifest、安装图标和仅缓存静态壳的 Service Worker；不能离线操作候选、获取新证据或代替真实手机安装验收。
