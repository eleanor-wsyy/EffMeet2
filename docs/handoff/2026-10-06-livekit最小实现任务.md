# LiveKit 最小实现任务 · 2026-10-06（A 发起，组长指令）

> 背景：B 的联调核对列出「LiveKit 远程音轨未实现」。它是 D 今天接 `apps/web` 的依赖——没有它，"远程成员开麦说话"在演示里是空话。组长拍板：**今晚补最小实现，不走降级**。

## 目标（最小可用，别贪）

两个浏览器（或一浏览器一手机）加入同一会议，远程成员的声音能进现场链路；`apps/web` 里能加入/离开/静音。

## 最小范围

1. **房间与 token**：用 LiveKit Cloud 免费层（或本地 `livekit-server` 容器）。token 必须**服务端签发**（`services/relay/` 加一个签发端点），API Key/Secret 只存服务端 `.env`，不进前端、不进 git。
2. **relay 侧**：`services/relay/` 已有 `media.py`/`protocol.py` 雏形，在其上补：创建/加入房间的 HTTP 端点 + 音轨订阅转发到 ASR（远程音轨 → FunASR → `channel=remote` 的 UtteranceFinal）。
3. **web 侧**（D 接）：LiveKit JS SDK，`apps/web` 入会页三个动作：加入、离开、静音（麦克风开关）。
4. **权限**：远程成员只能发布自己的麦克风轨；不能订阅他人身份；token 与会议绑定（room name = meeting_id）。

## 不做（今晚不做）

- 不做视频轨（纯音频）
- 不做录制/回放（那是 10.07 E 的事）
- 不做美颜/降噪调优
- 不做多端房间管理 UI

## 验收（今晚冻结前）

- [ ] 两个浏览器进同一会议，互相能听到说话
- [ ] 静音开关生效，对方可见静音状态
- [ ] 远程音轨被转写为 `channel=remote` 的 UtteranceFinal 落盘（账本可查）
- [ ] 断网重连后自动回房，不重复发音轨
- [ ] token 接口不出现在前端代码里
