## 2. 最快复现路径：无需账号、模型或硬件

所有命令在项目根目录 PowerShell 执行，路径使用单个反斜杠。本机已有 `.venv`；换电脑需自行安装 Python 3.11+ 并重建环境，不能直接复制虚拟环境。

```powershell
# 新电脑首次安装，已有 .venv 时跳过第一行
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/smoke_bench.py
```

预期：59 项测试通过，冒烟输出 `status: PASS`。冒烟会自行启动临时本机服务、建立临时数据库、测试后关闭服务；不要求先运行 Demo，不调用真实千问，不发声。

冒烟闭环：合成 WAV → EFMA 帧 → 实际 WebSocket → 合成 FunASR 服务 → 最终发言入账 → 合成模型任务 → 本人确认 → 合成 PCM 下行 → 模拟排空回执 → 重试去重 → 事件断点恢复。网络传输是真的，ASR/模型/TTS/音频汇为测试替身。

## 3. 打开可操作的台架页面

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:EFFMEET_DB_PATH = (Join-Path (Get-Location) 'data/bench.sqlite3')
# 本机 Windows 有语音包时，可启用离线 TTS
$env:EFFMEET_TTS = 'windows'
.\.venv\Scripts\python.exe scripts/run_bench.py
```

打开 [本机台架](http://127.0.0.1:8768)，健康检查为 `/healthz`。用 Ctrl+C 停止；被占用时用 `--port 8769`，音频客户端同步更改 `--url`。服务是否仍运行以健康检查为准。

页面可新建会议、手工添加发言、提交模型任务、由本人确认/拒绝、查看命令回执、停止命令、查看原文记录。没有 Key 时分析会失败，完整无账号演示请用上面的 `smoke_bench.py`。不要把模型未配置当作程序已经产生候选。

控制器与媒体目前在同一进程。一个台架数据库只能运行一个进程、一个 worker；重启时会取消未完成任务，不能让第二个服务对同一数据库执行恢复。旧 mock Demo 可单独使用 `scripts/run_demo.py`（默认 8765），但必须用不同数据库，并确保 `EFFMEET_BENCH` 未设置为 `1`。

## 4. 配置项

`.env.example` 只是示例，程序不自动加载 `.env`。环境变量需在启动服务的同一个终端设置，更改后重启服务。

| 配置 | 默认 / 作用 |
|---|---|
| `EFFMEET_DB_PATH` | `run_bench.py` 默认项目下 `data/bench.sqlite3`；相对值按工作目录解释 |
| `EFFMEET_BENCH` | `1` 使通用 `create_app()` 使用台架；推荐直接运行 `run_bench.py`，不必设置 |
| `FUNASR_WS_URL` | 无默认地址；例如已启动的 `ws://127.0.0.1:10096`，非回环地址要求 `wss` |
| `QWEN_API_KEY` | 千问服务端密钥；不要发到聊天、前端或提交到仓库 |
| `QWEN_MODEL` | 默认 `qwen-plus`，真实接口兼容性仍需联调 |
| `EFFMEET_TTS` | `windows` 启用 Windows 离线语音；否则未配置 |
| `PYTHONIOENCODING` | 推荐 `utf-8`，便于中文日志显示 |
| `EFFMEET_CONTROLLER_URL` | 旧中继的预留变量，当前统一台架不读取它 |

`/healthz` 的 `asr_configured` / `tts_configured` 表示适配器已配置，不代表外部服务健康、模型权重已加载或扬声器已接通。当前 `hardware_connected=false`。

## 5. 音频输入与播放操作

先在网页创建会议，复制 `meeting_id`。以下尖括号内容均需替换。

```powershell
# 需要真实 FunASR 服务；文件必须为 16kHz、单声道、16-bit PCM WAV，最长 30 秒
.\.venv\Scripts\python.exe scripts/bench_audio.py --url http://127.0.0.1:8768 --meeting '<meeting_id>' upload 'F:\音频\sample.wav' --channel remote --speaker remote_1 --start-ms 0
```

客户端自动取得本机调试身份、配对、绑定来源、发送 EFMA 帧；服务在收到 `audio.end` 后调用 FunASR，完成结果写入账本。`start_ms` 是显式提供的会议时间偏移，不是自动同步的跨设备时钟。不能据此宣称已实现流式 VAD 或多人分离。

只有模型形成候选并由本人确认，才会产生 `command_id`。复制命令 ID，再运行：

```powershell
# 无扬声器：模拟下行消耗与回执，不发声；仍需要服务端 TTS 已配置
.\.venv\Scripts\python.exe scripts/bench_audio.py --url http://127.0.0.1:8768 --meeting '<meeting_id>' play '<command_id>' --safe-pause --simulate
```

`--safe-pause` 表示操作者确认当前可播报；服务还检查近期上行振幅活动与上下文。这个简单门槛未作声学标定，不能代替生产用 VAD/AEC。播报期间上行被阻止以避免自触发，不支持双讲。

去掉 `--simulate` 会调用 `sounddevice` 实际输出音频。该可选库未列入基础依赖，当前分支没有完成真实播放器依赖冻结及扬声器验收；接手人需先准备音频设备、安装并验证依赖，再测排空和停止。

## 6. 接口变更（供 B / D 接入）

| 接口 | 当前行为 |
|---|---|
| `POST /api/v1/meetings/{mid}/analysis` | mock 模式直接返回模拟结果；bench 模式返回 `job_id/status/replayed`，不再立即包含 `analysis` |
| `GET /api/bench/meetings/{mid}/jobs/{job_id}` | 查询 queued/running/completed/failed；完成后从 `result` 读取候选，失败看 `error_code` |
| `POST /api/bench/meetings/{mid}/media-bindings` | 主持人提交 config、speaker_id、channel、start_ms；先配对设备，再绑定会话 |
| `WS /device/v1/audio` | `Authorization: Bearer ...`，仅回环本机客户端；start → ready → EFMA/ACK → end → utterance.final/audio.closed |
| `WS /device/v1/playback` | 带配对凭据，先发 command_id/device_id/boot_id/safe_pause/sink_mode，再按握手收帧、ACK、回执 |
| `POST /api/bench/commands/{command_id}/stop` | 主持人或观点本人可取消；失败回执标记 `CANCELLED` |
| `GET /api/bench/meetings/{mid}/response-tracking` | 原观点、模型判断、可核对现场证据、本人核对结果 |
| `POST /api/bench/meetings/{mid}/claims/{claim_id}/response-verification` | 本人提交 `{"response_utterance_ids":["现场发言UUID"]}`；记录 manual / response.verified；取消相关未完成提醒 |
| `WS /api/v1/meetings/{mid}/events` | 首条 JSON 为 `{ "token": "本机会话凭据", "after_seq": 0 }`；收到有序事件，重连从最后 seq 继续 |

媒体连接不接受 URL 查询凭据或浏览器 Origin，网页不能直接用原生 WebSocket 调用这些设备接口。网页事件 WS 与设备音频 WS 的鉴权机制不同。旧 `/ws/audio/{session_id}` 和任意 `/api/tts/{session_id}` 上传入口已移除。

媒体绑定有效期 10 分钟、配对凭据检查有效期 1 小时；重新配对同一 device_id 会替换旧 token。`remote_1/remote_2` 是台架身份，不能当作正式远程成员权限系统。

命令确认后只是排队。当前目标固定为 `host_speaker_test`；校验目标 ID 不等于完整设备能力协商。TTL 检查针对领取后的开始播放阶段，未等同于设备端完整单调时钟执行策略。发送音频结束不等于播放完成，必须等匹配设备的 completed 回执；模拟汇的回执为 mock。

## 11. 本次补完：本地 ASR 与回应核对

终端 A 启动真实本地识别服务；首次下载官方公开模型需要网络，不需要账号。代码只使用安装包中的实现，`trust_remote_code=False`。SDK 首次还会建立用户目录 `.modelscope` 配置，需正常写入权限。

```powershell
# 新电脑首次准备；本机已有 .venv-asr 时跳过安装
python -m venv .venv-asr
.\.venv-asr\Scripts\python.exe -m pip install -r requirements-asr.txt
$env:PYTHONIOENCODING = 'utf-8'
.\.venv-asr\Scripts\python.exe scripts/run_local_asr.py
# 本机已下载，离线启动可明确使用缓存路径：
# .\.venv-asr\Scripts\python.exe scripts/run_local_asr.py --model data/models/models/iic--SenseVoiceSmall/snapshots/master
```

看到 `LOCAL_ASR_READY` 后，在终端 B 设置 `$env:FUNASR_WS_URL='ws://127.0.0.1:10096'`，再按第 3 节启动控制器。页面建会后按第 5 节上传 WAV。本机测试文件为 `data/asr-synthetic-input.wav`（合成语音，未纳入交接源码），可复用测试或换成经授权的 16k mono PCM WAV。

真实上行验收记录：会议 `5b9441b4-df54-472c-ba26-363421b4a0ab`，事件 `e5c3083b-f34c-4ea4-95a3-d13dcea324e1`，本机数据 `data/real-asr-check.sqlite3`。本条仅证明真实模型识别及入库，不含千问、真人录音或扬声器。官方模型用法参考 [SenseVoice](https://github.com/QwenAudio/SenseVoice)。

服务仅监听 127.0.0.1，拒绝浏览器 Origin；最大 30 秒、仅整段 offline、CPU 串行识别，繁忙时拒绝请求，不做说话人分离。Windows 中文路径下原 SentencePiece 原生文件接口失败，启动脚本通过 Python 读取模型字节再加载，未移动模型或修改安装包。`ffmpeg` 缺失警告不影响本台架直接传 PCM 数组。

回应核对复现（无 Key 可用 tests.network_fixture 合成模型，不能冒充真实千问）：

1. 新建会议，加入 remote_1 观点并分析，出现待本人确认候选。
2. 加入一条 onsite 现场回应；第 4 区显示“待核对”，不会自动变成已回应。
3. 勾选该现场发言，以 remote_2 提交，预期 `NOT_OWNER`；切回 remote_1 后提交成功。
4. 页面显示“已确认回应”；待确认候选变为 responded，排队命令产生 `RESPONSE_VERIFIED` 失败回执。正在播放的命令会被请求停止，无法撤销已发出的声音。
5. 再生成原文记录，所选现场证据标记 human_verified。同样提交幂等；更改已保存证据返回 `VERIFICATION_CONFLICT`，当前不提供撤回。

模型任务轮询已改成独立短轮询，等待期间可以继续输入或核对；若输入改变分析上下文，任务返回 CONTEXT_CHANGED，需重新分析。
