## 一、排机与耗材

1. **先问每种料有几卷，再排并行。** 现象：按"4 盘全并行"排好，结果黑料只有 1 卷 → 黑盘只能串行，排程作废。真相：一卷料同一时刻只能喂一台机。正确做法：排机前先确认灰/黑各几卷；黑 1 卷=黑盘串行，灰 2 卷=灰盘可 2 台并行。
2. **黑料紧张时，把"可灰"件改灰释放瓶颈。** 现象：黑盘 3 轮串行卡死。真相：PLATE-RUNBOOK 标注 B2 机构件"急用可灰"、B3 支架件"可灰"（壳内不可见，颜色纯外观）。正确做法：机构/支架改灰，用闲置灰卷并行；只把**外露件**（面板/短颈/滑盖/键帽）留给黑料。
3. **换料顺序：灰→灰→灰→黑，黑放最后。** 省一次洗喷嘴/换料停机。
4. **条件完全一致（颜色×层高×机器×支撑）的盘可以合并省机时。** 例：B2 机构 10 件 + B3 支架 6 件同条件 → 并成一盘 16 件。但**单卷串行时合并反而更优**（1 盘 1 次 setup vs 2 盘 2 次）；多机并行时才拆盘。先想清楚是并行还是串行再决定拆/合。

## 二、3MF 与切片

5. **3MF 只是几何起点，"不叫已切片"。** 现象：以为拖进 3MF 就能打。真相：plates/*.3mf 只含床面排布，不含机型/材料/支撑。正确做法：进 Bambu 必须手动选机型+耗材+设工艺；别把 3MF 当成品切片。
6. **喷嘴直径会过滤工艺预设下拉。** 现象：H2S 上找不到 0.4 的工艺预设。真相：H2S 默认喷嘴 0.2，下拉只显示 0.2 喷嘴预设，0.4 基的被隐藏。正确做法：先把「喷嘴→直径」改 **0.4**（学校是 0.4 硬化钢），下拉才出 0.4 预设。所有壁厚/墙层数计算都按 0.4。
7. **"空层无法打印"≠网格坏了。** 现象：切片报 P07–P10/P16"模型在X和Y之间出现空层，无法打印"，橙色一大片。真相：逐Z三角面跨距验证**无真空层**；实为薄于 0.4 喷嘴的薄鳍被切片丢弃。正确做法：别被警告吓停整盘；拆 **SAFE**(零警告)/ **THIN**(勾**检查薄壁**) 两盘，SAFE 先打，THIN 的薄鳍缺几道不影响结构主体。
8. **条件显示的参数找不到就别卡机时。** 现象：找不到「顶部Z距离」。真相：要先「开启支撑」+ 面板顶部「高级」开关打开才显示。正确做法：找不到用默认 0.2 可接受，跳过继续；别为 0.05 的间隙耽误抢来的机时。

## 三、Bambu Studio 预设（重灾区）

9. **外部手写预设注入会被 Bambu 删掉。** 现象：把预设 .json/.info 塞进 `%APPDATA%/BambuStudio/user/<id>/process/`，重启后文件消失、下拉没有。真相：Bambu 启动时清理不认的外来 setting_id/base_id。正确做法：**复用预设只能 UI「保存为预设」**；UI 存的会保留（version 2.6.0.5 那批活着）。别再试外部注入。
10. **Bambu 日志是 .enc 加密，读不了。** 排查预设/切片问题别 grep 日志；靠看 `user/<id>/process/` 文件存留 + UI 表现 + 读盘核对预设 .json 内容。
11. **简中参数名以本地化文件为准，别凭印象。** 查 `安装目录/resources/i18n/zh_cn/BambuStudio.mo`（gettext）。对照：Wall loops=**墙层数**（不是壁圈数/墙体数）、Gyroid=**螺旋体**、Detect thin wall=**检查薄壁**、Top Z distance=**顶部Z距离**、Enable support=**开启支撑**、Part cooling fan=**部件冷却风扇**、Bed temperature=**床温**。写文档/口述参数一律用这些真名。
12. **床温不在工艺预设里。** 真相：床温/首层床温属**耗材**设置，工艺预设存不进。正确做法：每次换盘在耗材里确认床温 65，或把改好床温的耗材也「保存为预设」。
13. **冷却风扇的真名和位置。** "零件冷却风扇"不存在；简中是**部件冷却风扇**，控制前几层的是**起始层风扇**(设0) 和 **满速风扇在**(设第4层)。用工艺下拉旁放大镜搜真名最快。
14. **预设按 层高×机型 分版，别混用。** 0.20H2S 只打 H2S 的 0.20 盘；0.16H2D 只打 H2D 的 0.16 盘。颜色靠**耗材**选，跟工艺预设无关（同一 0.16H2D 预设可打灰 G3p 也可打黑 B1p）。
15. **存完预设立刻读盘核对。** UI 存的可能漏项（例：0.16H2D 漏存稀疏填充图案，还是默认 grid）。读 `user/<id>/process/<名>.json` 逐项对 RUNBOOK 要求，缺的补存。

## 四、炒面（脱板）排查序

16. **炒面=整件脱板被拖成面条。按序查：** ① **悬空处有没有支撑**（P02 中心颈孔悬空，漏开支撑→下垂→喷嘴撞飞整件，最常见）；② **床附着**：Brim 加宽到 10 + 床温 65 + 纹理PEI板洗洁精水洗/IPA 擦（手印=脱模剂）+ 首层速度 25–30 + 前几层关风扇（起始层风扇0/满速风扇在4）；③ 门关好防穿堂风、腔温<40。
17. **大平板+接触面只有一圈环=高翘边风险。** P02"接缝圈朝下"接触面小，附着天生弱；Brim/床温/首层速度三件套必上。仍失败再升级：开**筏层**(代价底面糙)→ 或**翻面**(装配面朝上，牺牲平整度换成功率)。
18. **预览必查两点再点打印**：悬空处下方有树支撑；底面一圈有加宽 Brim。

## 五、样片与数据纪律

19. **轴承配合件等 S1 样片，纯几何件可先打。** P05/P06/P11/P12（6806 座孔/空心轴）务必等 S1 PETG 样片过；P07–P10 支柱/P13 限位/P30/P31 线鞍纯几何可先打。PETG 结论**不跨材料**套用到 PLA。
20. **到货当天先卡尺再重建，别等。** LCD 四孔漏测导致 P23/P24/P25 长期阻塞；屏早就在手边。按 [MEASURE-TODO.md](MEASURE-TODO.md) A 组（中午可测）当天量完回填，解锁面最大。
21. **试打≠放行。** 开打不改变状态：`CANDIDATE_NOT_RELEASED` / `slicer_status=NOT_RUN` / 26 项测试 NOT_RUN / 三个放行布尔 false 保持；未实测不填 PASS。教训集本身也不构成任何放行。

## 六、追加教训（2026-10-15 晚 · 空层警告真凶更正）

22. **"空层无法打印"的真凶是墙层数过多，不是网格坏。** 现象：spacer/P16/P20 报"模型在X和Y之间出现空层"；manifold3d 逐层截面证明几何不空（P20 该层 66mm²）。真相：墙层数6×0.42线宽=2.52mm > 薄特征宽（2.4壁/2mm柱/1.6唇），切片器塞不下6圈→整层丢弃→上半悬空炒面。正确做法：**墙层数=4**（或墙生成器=Arachne+检查薄壁）。曾误判为"环状导出网格坏"并解析重建spacer——重建无害但没治到根；根在切片参数。
    > **⚠️ 2026-10-16 更正（机制部分不成立，原文保留）：** 用 `tools/thinwall_audit.py` 对全 31 件逐层实测（E=0.42, lh=0.2）：**空层 0 个、`k_max≤1` 的层 0 个、thin_frac 最大仅 1.53%（P28）**。P07–P10 实测 thin_frac=0.00%、P16=0.10%、P20 环壁 2.20mm→k_max=3＋墙心残隙 0.098mm。
    > 两点被推翻：①**墙层数设得比几何能容纳的圈数大，不会丢层** —— 经典墙生成器只是不生成多余圈（`offset(-(k-0.5)E)` 为空即停），"6 圈塞不进 2.4 壁→整层丢弃"的因果不成立；②`6×0.42=2.52` 只算了**单侧**墙，而 2.2–2.4mm 是**环形/双侧**壁，墙从内外两侧同时生成，k_max 由 `W=(2k-1)E` 决定（2.20→k=3、2.40→k=3），跟"6 圈"无关。
    > 仍然成立的部分：**"空层警告≠网格坏"这个方向是对的**，几何扫描确实 clean。但真机制是 RUNBOOK:90 记的另一条 —— **薄于一道挤出的薄鳍在「检查薄壁」关闭时被整片丢弃**；而 P07–P10/P16 现已测不出薄特征，因为 RUNBOOK:72 记的修复（P07–P10 换解析干净管、P16 改杯口朝上）**已经生效**，本条描述的是修复前的几何。
    > 结论：墙层数 4 可以留着（无害、够用），但**别再把它当"空层/缺特征"的病因**。查这类问题用 `tools/thinwall_audit.py` 的 thin_frac，不是数墙圈。
23. **几何扫描与切片警告矛盾时，信扫描+查切片参数。** manifold 截面 clean 但切片报空层 → 一定是切片设置（墙圈数/线宽/薄壁开关）问题，别去修网格。
    > **2026-10-16 补充：** "查切片参数"要查对参数。实测证明**墙圈数不是**这类警告的成因；该查的是**「检查薄壁」开关**与**支撑范围**。且"信扫描"的前提是扫描本身量对了东西 —— 只查"该层面积是否为 0"会漏掉"薄鳍被丢弃"（面积不为 0 但特征没了），必须加形态学开运算量 thin_frac，见教训30。

24. **照片定性发现能拦下数字拦不下的设计坑。** 学妹直尺数字全废（±0.5 判不了公差），但一张"焊盘外凸"照片直接判死 P21/P22 压圈和 P01 壁袋（ID14.6 装不进 17–18 宽的模块）。教训：收货先拍**形状特征照**（凸出/侧焊/盖类型/标签），比急着读数值钱；读数交给卡尺，形状交给照片。
25. **湿料是炒面的隐藏主因之一。** 黑卷连犯三次炒面+满床拉丝、灰卷不犯 → 受潮 PLA。设置/朝向/支撑全排除后仍炒面且伴随拉丝=烘料（45–60℃ 4–6h）或换卷，别继续调参数。内部件可先改灰料（RUNBOOK"可灰"）不饿机器。

## 七、追加教训（2026-10-16 · 机房老师/学妹交付/收尾）

26. **过密网格要减面再出盘。** Blender 螺旋/布尔件动辄 1.8万–6万三角面，切片周长路径过密、内部碎填充、打印慢。修：平面融解（DECIMATE/DISSOLVE）——平面件 5°、曲面配合件 1.5°；**验收阈值：体积差<0.3% 且 bbox 逐位不变**（P02 5° 时体积-1.37%/外形缩0.1mm 被拒，1.5° 通过）。减面脚本在 `tools/decimate_planar.py`。
    > **⚠️ 2026-10-16 更正（面数必须数三角面，不能数多边形）：** DISSOLVE 把共面三角形并成 **n-gon**，`len(bm.faces)` 会大幅下降，但 **STL 只存三角形**，n-gon 重新三角化后数量可能完全不变。实测（`tools/decimate_planar.py --dry-run`，Blender 4.5.3）：
    > - **P02 @1.5°：STL 三角面 18134→13614（−24.93%）**，n-gon 18134→5231，dVol 0.0775%，dBbox 0 → **真减面**，入仓的 `decimated/P02_decimated.stl`(13614) 可复现、正确。
    > - **P04 @5.0°：STL 三角面 4896→4896（0%）**，n-gon 4896→1266，dVol 0.0002%，dBbox 0 → **彻底 no-op**。HANDOFF 记的"P04 4896→1266"是**拿三角面数比 n-gon 数**，量纲错误；`decimated/P04_decimated.stl` 实为未减面副本，`TMP-INTERN2-DEC` 盘内 `P04_DRIVER32T_dec` 也正是 4896 面。**机房老师反映的"网格过密"对 P04 从未解决。**
    > 只有当平面区**含内部顶点/内部边**时，DISSOLVE 才真能减少三角面（P02 是、P04 不是）。要减 P04 这类以圆柱/齿为主的件，须换能删内部顶点的方式（DECIMATE/COLLAPSE 或 remesh），并重新过阈值。
    > 脚本已加三道闸：三角面无下降→`NO_TRI_REDUCTION`；超阈→`REJECT_*`；落盘面数≠减面后→`EXPORT_MISMATCH`；均不产出可信产物。另：旧脚本 OUT 指向已失效的会话临时目录，产物从未真正入仓，已改为 `plates-merged/decimated/`。
27. **"打实心"先分两类再回应老师。** 截面≤2.5mm 的全墙件（P28/P27/P25/P13/P32壁/P14管壁/P20柱环）没有芯，实心=设计正确；厚件（P02/P04/P05/P11/P16/P01/P23）应出螺旋填充，若预览实心先查 稀疏填充密度15%/图案螺旋体/墙层数4，别先怀疑建模。
28. **验收队友交付先查量具精度。** 学妹直尺(±0.5)数字全废但她纪律好（不填没把握的数）；照片定性反而立功（ZZ盖/型号/焊盘外凸）。教学指南要嵌实物图（大学生看图认件快），并写明"读不出就留空+补拍要求"。
29. **会话收尾前扫"内容滞后"而不只"文件同步"。** git status 干净≠文档跟得上实物：HANDOFF/README/手册常落后于当天决策，收尾时逐份对齐再推。

## 八、追加教训（2026-10-16 · P20「圆孔打不出来」排查 —— 含一次自我纠错）

30. **【已撤回原结论】"墙层数过多致整层丢弃"是错的；P20 几何无罪，病因不在模型也不在墙层数。**
    > **原教训30（本日早些时候写入，现撤回）**：称 P20 环壁 2.20mm、`6×0.42=2.52>2.2` 塞不下 6 圈→整层丢弃→圆孔打不出，且"改 4 没用是因为预设没重存"。**该结论错误**，错在两处：①`6×0.42` 只算单侧墙，环壁是内外**两侧**同时生成，k_max 由 `W=(2k-1)E` 决定；②墙层数设得比 k_max 大**不会丢层**，生成器只是不生成多余圈。
    >
    > **实测（`tools/thinwall_audit.py`，manifold3d 逐层偏移腐蚀 + 形态学开运算；线宽取自实存预设：外墙 0.42 / 内墙 0.45，lh=0.2）**：
    > - P20：`genus=2`（两孔全程贯通）、**空层 0**、**`k_max=2`**、残隙 **0.91mm**（由 gap fill 接管）、thin_frac **0.00%**、判 **CLEAN/OK**。第 3 圈中心线 `d₃=0.42+1.5×0.45=1.095` > 环壁半厚 1.10，只剩 0.005mm 退化脊线 → 被丢弃。**完全可打印，不存在过挤。**
    > - 全 31 件：空层 **0**、FAIL_THIN **0** 件、thin_frac 最大 **1.53%**（P28）。
    > - 盘内核对：`TMP-INTERN2-DEC` 里 `P20_TACT_HOLDER` = 1236 三角面，与 `candidate-stl/P20_TACTILE_HOLDER_UNVERIFIED.stl` **逐面一致**；朝向 36×14 面朝下、柱朝上，正确。
    > - **Bambu Studio 本机 `--info` 独立印证**：`manifold = yes`、`number_of_facets = 1236`、`36.000×14.000×8.600002`、`volume = 1752.106689`（与 manifold3d 的 1752.108 一致）。
    > **结论：模型、盘、朝向、壁厚、墙层数全部无罪。改建模（如把柱 Ø7→Ø6.8 凑阶梯）没有依据，不要做；调墙层数也没有用（6/4/2 对 2.20mm 环壁都只生成 2 圈）。** 排查方向转挤出/耗材（教训32）与支撑范围（教训31、34）。
    >
    > **⚠️ 本条自身也错过一次（第二次更正）**：早先用**单一 E=0.42** 算，得出 `k_max=3`、残隙 `0.0979mm`、"4.3× 过挤"。那是错的——Bambu classic 生成器**第一圈用外墙宽 0.42、后续圈用内墙宽 0.45**，中心线距离是 `d_1=0.5×外`、`d_k=外+(k-1.5)×内`。用真实双宽后 k_max=2、残隙 0.91mm、判 CLEAN。见教训35。
    >
    > **方法论教训（比结论更重要）**：本次连错三轮，都是**拿一个听起来合理的算式当结论**、没先量。正确顺序是：先用量具（逐层截面/开运算/面数回读/**实存预设的真实线宽**）拿到数，再谈机制。仓库既有三关（`delivery-validation.json` 只查 closed+正体积、`export-byte-audit.json` 只查 watertight+零面积面、教训22 的截面审计只查"该层面积是否为 0"）**都量不到"特征做不做得出来"**，所以补了 `tools/thinwall_audit.py`。

31. **对症的切片设置必须写进全局表，不能只挂在某一盘的行里 —— 否则件一换盘，修复就丢了。**
    RUNBOOK:85 早已诊断过 P20：「NIGHT 四废（P04/**P20**/P21/P22）病根＝**支撑长进口袋/孔洞**＋压圈立打」，对症方案是 BNIGHT2 行的「**支撑＝仅在打印板生成**」。但那条设置**只写在 BNIGHT2 一行**：§2 全局表(:35) 和 §5 切片参数(:87) 都只写「开启支撑＝开、树状」，**没有"仅在打印板生成"**。P20 从黑盘(BNIGHT2)挪到灰盘(INTERN2-DEC)后，**这条修复就没人再看到**——而 INTERN2-DEC 在 RUNBOOK 里**根本没有条目**。这解释了"失败了无数次"：每次换盘都从零猜设置。
    正确做法：①对症设置一律上升到 §2 全局表；②**每个新盘必须在 RUNBOOK 有一行**（盘名/料/层高/机器/件/支撑/Brim/特别注意），无条目不许上机；③盘名改动或件换盘时，回头核对该件的历史病根有没有跟着搬过来。

32. **「App 报成功、实物失败」优先怀疑挤出/耗材，其次才是切片。** 判据看**断口形貌**：
    - **断口平整、顶面是规则层纹** → 切片/设置问题（层确实没生成，或特征被丢弃）。
    - **断口粗糙不规则、多个件停在**不同**高度** → **挤出中断**（堵头/料尽/湿料气泡），打印机照走完路径所以报满层。
    本次照片属**后者**：5 件里 3 件只有下半截、断口粗糙、停在互不相同的高度。这是材料/挤出故障的典型形貌，不是切片能造成的。叠加教训25（黑卷受潮已确认）——**灰卷也应复测含水**，别因为"灰卷之前没犯"就排除。
    另一条硬线索：App 显示 **128/128 层**，但仓库 `TMP-INTERN2-DEC` 最高件 14.4mm，0.20 层高只有 **72 层**。**128≠72**，说明实际跑的工程与仓库盘不一致（层高/朝向/内容被改过，或另存过）。**排查前先把 Bambu 里那个工程导出成 3MF 入仓**，否则所有分析都对不上实物。

33. **无源件是隐患：只存在于 3MF 内部、仓库里没有建模源的件，无法审计也无法复现。**
    `P32_HOLDER_L/R`（麦胶座）与 `P18T_CRADLE`（USB-C 容差托架）**不在** `build_v6.py`、**不在** v6 blend（374 个对象里无匹配）、**不在** `candidate-stl/`、**不在** `PARTS.csv`（31 件 P01–P31）。它们只活在 `TMP-INTERN2-DEC` / `TMP-MICHOLDER` 的 3MF 里。后果：①`finalize_exports.py` 会重写 PARTS.csv，手工登记会被冲掉；②没有源就无法改参数重出（本次 P32 若要动腔径，无从下手）；③违反 AGENTS.md「模型/BOM/说明/manifest 同步」。

35. **算薄壁必须用真实的内/外墙两套线宽，用单一 E 会凭空造出"过挤"假象。**
    Bambu/Prusa **classic** 周长生成器：第 1 圈是外墙（宽 `outer_wall_line_width`），第 2 圈起是内墙（宽 `inner_wall_line_width`）。中心线到边界距离：
    `d₁ = 0.5×外`，`d_k = 外 + (k-1.5)×内`（k≥2）；第 k 圈存在 ⟺ `offset(-d_k)` 非空。
    k 圈恰好填满的壁厚：**W = 2×(外 + (k-1)×内)** → 外0.42/内0.45 时 k=1→0.84、k=2→1.74、k=3→2.64、k=4→3.54。
    本次踩的坑：用单一 E=0.42 套 `(2k-1)E` 公式，把 P20 的 2.20mm 环壁算成 `k_max=3`、残隙 0.0979mm、"4.3× 过挤"，据此差点得出错误结论。用真实双宽实为 **k_max=2、残隙 0.91mm、CLEAN**。
    `tools/thinwall_audit.py` 已改为 `--eouter/--einner` 双参数并加退化脊线过滤（残隙 < 5%×内墙宽 视为会被丢弃的脊线，不计入 k_max）。**改切片参数前先读预设拿真实线宽**（教训34）。

36. **本机 Bambu Studio CLI 能读不能切：`--info` 可用，`--slice` 必崩。**
    `bambu-studio.exe --info x.stl` 正常输出面数/尺寸/manifold/体积，是**独立于 manifold3d 的第二套几何核对**，很好用。
    但 `--slice 0`（含 `--export-3mf` / `--export-slicedata`）在 **H2S 与 A1 两种机型预设下均段错误** `0xC0000005`，崩在 `DynamicPrintConfig::update_values_to_printer_extruders_for_multiple_filaments` 的 "different nozzle volume processing"，**发生在预切片之后、导出之前**（日志已见 `is_support_necessary`、`m_support_used`）。
    → **拿不到 G-code**，"支撑是否真长进某孔"这类问题**无法离线证实**，只能靠 Bambu GUI 预览。写文档时不要把 CLI 崩溃当成"切片失败"，也不要据此推断打印结果。
