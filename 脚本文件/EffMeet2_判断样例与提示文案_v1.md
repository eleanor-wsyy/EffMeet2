# EffMeet 2 候选判断样例与提示文案 v1

> 配套：接口契约 v1（`AnalysisResult.status` 三态）、B 端已实现参数（候选 TTL **120 秒**）。
> 分工边界：本文档由 A 负责（规则语义与文案）；B 负责证据、长度、安全校验、确认与回执的工程实现。

---

## 1. 判断总表

**核心规则：只有 `possibly_unresponded` 会产生候选；其余一律弃权——弃权 = 不生成 `intervention.created` 事件，不是"生成后再拦截"。**

| 状态 | 含义 | 产生候选？ | 界面表现 |
|---|---|---|---|
| `possibly_unresponded` | 线上观点明确、现场尚无关联回应 | ✅ 是 | 弹出候选确认卡 |
| `responded` | 现场已有可关联的回应 | ❌ 否 | 无打扰；观点地图标"已回应" |
| `uncertain` | 证据不足/语义模糊/说话人不明 | ❌ 否 | 无打扰；观点地图标"需人工核对" |
| 本人不在场 | owner 无活跃会话（掉线/暂时离开） | ❌ 不弹卡 | 候选静默保留至过期；本人回到会议时在"待确认"列表可见，不主动打扰 |

**候选生成前置条件**（全部满足才评估）：
1. 最终转写（partial 不进判断）
2. 明确的线上发言人（`speaker_id` 非空；识别不出人 = 放弃）
3. 与当前议题相关
4. 尚无可核对的回应

**触发后约束**：
- **TTL 120 秒**：倒计时结束未确认 → 自动弃权，界面标"已过期"
- **单观点去重**：同一观点只产生一次候选，不重复弹卡
- **全局冷却**：每次播报后 **60 秒**内不再产生新候选（防连续打扰；建议值，可调）
- **播报前复核**：确认后仍等现场安全停顿，且开口前再次检查是否已被回应——已被回应则静默取消
- **串音/多人混说/会议已结束** → 直接弃权或标"需人工核对"

## 2. 四类样例

### 样例 A：可能未回应（`possibly_unresponded`）→ 产生候选

- **场景**：丙（线上）说"满溢检测用重量传感器比摄像头便宜很多"，随后 40 秒现场两人继续争折叠结构，无人接话。
- **判定依据**：发言来自明确线上身份；内容与当前议题（成本/结构）相关；无任何现场发言与之关联。
- **系统行为**：生成候选卡，等本人决定。

### 样例 B：已经回应（`responded`）→ 弃权

- **场景**：丙说完重量传感器后，甲 10 秒内接话"有道理，这个比摄像头方案省一半预算"。
- **判定依据**：存在可关联的现场回应（时间邻近 + 语义关联）。
- **系统行为**：不产生候选，不弹卡；观点地图上该观点标"已回应（AI 推测，待本人核对）"。

### 样例 C：不确定（`uncertain`）→ 弃权

- **场景**：现场两人同时说话，转写文本破碎；或丙的表述含糊（"呃这个好像也行吧"）。
- **判定依据**：证据不足以支撑"未回应"结论。**拿不准就放弃，宁可漏提醒，不可误打扰。**
- **系统行为**：不产生候选；观点地图标"需人工核对"，由本人会后确认。

### 样例 D：本人不在场 → 不打扰

- **场景**：候选生成时丙刚好掉线，或切出了会议页面。
- **判定依据**：owner 无活跃会话。
- **系统行为**：候选卡**不弹出**；120 秒 TTL 照常走；丙回到会议时在"待确认"列表看到它（若已过期则显示过期态）。**绝不在本人缺席时由系统或他人代为决定。**

## 3. 提示文案

### 3.1 机器人短句（宠物形态 · 语气规范）

**规范**：温和、简短、有礼貌；**不假装脆弱、不讲笑话、不卖萌、不替人做决定**；引用观点 ≤ 30 字（超长的由服务端压缩为本人原话摘要，不即兴改写）。

- **主模板**：
  > "打扰一下——刚才线上成员提到〈观点摘要〉，现场可以回应一下吗？"
- **示例（演示脚本场景）**：
  > "打扰一下——刚才线上成员提到，满溢检测可以试试重量传感器，成本会低一些。现场可以回应一下吗？"
- **变体 · 更短版**（现场节奏快、适合简短插入）：
  > "线上有位成员的观点还没被讨论到：〈观点摘要〉。"
- **不说的**："我觉得……""大家为什么不理他""求求你们听一下"——任何情绪表演和立场站队都禁止。

### 3.2 候选确认卡（远程成员界面）

- 标题：**你的观点可能还没被现场听到**
- 证据区：本人原话 + 发言时间（如"2 分钟前 · 你说的：'满溢检测用重量传感器……'"）
- 按钮：「**请机器人提醒**」 / 「**不必提醒**」
- 辅助说明（小字）："机器人会在现场停顿时转述你的原话；提醒前会再确认一次现场是否已回应。"
- 倒计时："XX 秒内有效"（120 秒倒数）
- 过期态："这条提示已过期。它仍保留在会后观点地图里。"

### 3.3 界面状态提示语

| 状态 | 文案 |
|---|---|
| 录音中 | 录音中（红点常亮，不闪烁） |
| 等待确认 | 等待你的决定 |
| 已确认待播报 | 好的，等现场说完这句话就提醒 |
| 播报中 | 正在提醒现场…… |
| 已完成 | 已提醒，现场回应会关联到你的观点 |
| 已过期 | 已过期，未打扰现场 |
| 需人工核对 | 这条关系不确定，请会后核对 |

### 3.4 与 B 当前实现的对齐说明

B 的 mock 界面按钮现为"请机器人向现场提示 / 不用向现场提示这条观点"。**建议统一替换为本文 §3.2 的「请机器人提醒 / 不必提醒」**——更短、主语是"我"（本人），符合"本人决定"的产品语义。文案归 A 管，B 照此更新字符串即可，不动逻辑。

## 4. 给千问的规则提示（prompt 语义骨架，A 维护）

1. 你只判断"该线上观点是否已有可关联的现场回应"，输出三态之一 + 证据 utterance_id；**不判断观点对错，不评价任何人**。
2. 证据不足、说话人不明、语义模糊 → 一律输出 `uncertain`。
3. 引用必须来自同一会议的原始发言 ID；没有证据不许输出"被忽视"类结论。
4. 你的置信度只是参考值，不是概率；宁缺毋滥。
