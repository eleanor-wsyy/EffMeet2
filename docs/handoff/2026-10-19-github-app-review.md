# 2026-10-19 · GitHub 新版用户端 APP 审查

> 审查对象：`origin/main` 上 `dea143d..c38ffb4` 的 `apps/web/`。
> 结论：这是**独立本地演示版**，不是当前已接控制器/LiveKit 的功能客户端。
> 本轮未把它合入本地 `apps/web/`，避免覆盖正在联调的功能版。

## 新版是什么

- 单页 PWA：首页 / 会议 / 历史 / 我的四个主页面，另有加入会议、快速会议、
  预定会议、扫码加入、观点地图、会议详情、设置。
- 数据层 `store.js` 全部写 `localStorage`（键 `effmeet2.local.v1`），
  会议、观点、转写、AI 提示、额度、联系人都是本地生成。
- 自带 32 项 Node 测试；解出后 `node --test tests/state.test.js` 全部通过。
- 视觉明显升级：透明底机器人主视觉、Zoom 式会议舞台、腾讯会议风格底部控制栏、
  观点便签按发言者着色、完整转写时间线、套餐/额度/设置页。

## 明确边界（来自新版 README 与代码）

- **不连接真实后端**：没有 `fetch('/api/*')`，不调用控制器、`/healthz` 或任何 API。
- **不连接音视频**：会议音视频传输未接；摄像头仅本机自预览，扫码也只在本机处理。
- **不连接 ASR/AI/机器人**：实时转写、千问、机器人播报、回执均为演示数据。
- 页面内多处明确标注“模拟/演示数据”“音视频与语音识别尚未接入”。

## 与当前功能版的关系

| 能力 | 当前本地 `apps/web/` | GitHub 新版 |
|---|---|---|
| 控制器 API | 已接 | 不接 |
| 本人确认/TTL/幂等 | 已接真实后端 | 本地模拟 |
| LiveKit 远程音频 | 已接发布 + 主持人订阅播放 | 不接 |
| 观点地图/证据导出 | 已接后端 | 本地 `localStorage` |
| 首页/历史/我的/扫码/设置 | 无 | 有，视觉完整 |
| 适合用途 | 真实演示、联调、验收 | 产品视觉/交互演示、视频素材 |

## 建议与已落地方式

1. **10-21 前不要直接合并**：新版会覆盖 `apps/web/app.js`、`index.html`、`styles.css`，
   丢失真实 API、LiveKit、本人确认与证据链。
2. **已落地**：新版复制到 `apps/web-demo/`，控制器挂载 `/app-demo/`；
   功能版仍是 `/app/`，两者互不影响。`tests/test_participant.py` 增加了
   `/app-demo/` 静态资源与路径穿越保护测试。
3. 若要把新版作为主界面，需要先做数据适配层：用 `store.js` 的接口替换为
   控制器 API，并重新接回本人确认、LiveKit、观点地图与证据导出；这是一次
   中等规模重构，不建议在初赛前冒险。
4. 新版可复用的部分：首页/历史/我的/设置/扫码 UI、机器人主视觉、会议舞台与底栏样式；
   可逐块迁移到功能版，而不是整体替换。

## 复现方式（不覆盖工作区）

```bash
# 只解出远端 apps/web 到临时目录
git archive origin/main apps/web | tar -x -C /tmp/effmeet-web-next
cd /tmp/effmeet-web-next/apps/web
python -m http.server 8000
# 打开 http://127.0.0.1:8000/
```

本轮已实际打开首页、会议页、快速会议页，并跑通新版自带 32 项测试。

控制器启动后也可直接访问：

```text
http://127.0.0.1:8765/app-demo/   # mock 模式
http://127.0.0.1:8768/app-demo/   # bench 模式
```

`/app-demo/` 只提供新版静态演示，不调用控制器 API；真实会议仍用 `/app/`。
