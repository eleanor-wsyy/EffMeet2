# D 端界面说明 v1 · 移动优先 PWA + 可选安卓壳

> 给 D（明天 10.06 接管 `apps/web`）的产品方向说明。A 定调，10-05。
> 一句话：**主线是移动优先的 PWA 网页；安卓壳只是条件触发的展示件，永远不进主演示链路。**

---

## 1. 决策与纪律

| 形态 | 定位 | 触发条件 |
|---|---|---|
| **移动优先 PWA**（主线） | 远程成员的唯一入口：入会、看原图、确认候选、观点地图 | 无——这就是原计划 |
| 安卓 WebView 壳 APK（可选） | 评委问"有没有 APP"时的展示件 | **10-07 中午前 Web 全流程跑通才允许开工**；只做三个画面（入会、确认卡、观点地图）；崩了不影响演示 |
| 原生/Flutter 重写、iOS、小程序 | 不做 | — |

纪律三条：

1. PWA 必须可"添加到主屏"（manifest + 图标 + 全屏 standalone）——演示录像里从主屏点开全屏应用，与真 APP 视觉无差别，这就是路线 B"仅需平板或手机"的证据。
2. 麦克风权限被拒时必须**可见提示并给重试引导**，不静默降级（这条本来就在 D 的验收里，移动端浏览器尤其重要）。
3. APK 若做，单独目录 `apps/android-shell/`，不污染 `apps/web`；任何人不许为壳改 Web 代码。

## 2. 三个核心画面（线框稿 v2，Figma 可编辑）

线框以 **SVG 交付，直接进 Figma**：`assets/wireframes/屏1_会中-远程成员_v2.svg`、`屏2_会后-观点地图_v2.svg`。

**导入方法**：Figma 画布上直接把 SVG 文件拖入（或 File → Place image，Ctrl/Cmd+Shift+K）。图层结构（frame/文本/图形）完整保留，全部可继续编辑。注意：原稿字体是 Sarasa Gothic SC，团队字体库没有的话导入后全选文字统一换成你们的设计字体即可。

D 照信息架构实现，视觉风格自定但遵守三条：状态色只用红（录音中）/绿（已回应）/黄（待核对/可能未回应）；确认卡是**浮层**；字号手机端正文 ≥14px。

1. **会中页**：现场原图 + AI 描述（可点核对原图）、我的观点列表（带状态标）、候选确认浮层卡（标题/原话/「请机器人提醒」「不必提醒」/倒计时）、录音中红点常亮
2. **观点地图页**：统计条 + 观点卡（提出人、状态、回应摘要、查看原话）+ 导出
3. **入会页**（PWA 首页）：输入会议链接/粘贴邀请 → 填名字 → 麦克风授权引导 → 进入会中页

## 4. 移动端特有注意点

- 竖屏优先，不做横屏适配；iOS Safari 与安卓 Chrome 各过一遍麦克风授权流程（两者权限文案和时机不同）
- 页面要在 4G 弱网下可用：原图单独加载占位、事件列表先文字后图
- 任何按钮热区 ≥44px；确认卡两按钮必须拇指可达（下半屏）
